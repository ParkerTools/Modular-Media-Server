01 · Start here

Getting started

You do not need a giant server to begin. A NAS, mini PC, used desktop, laptop, Raspberry Pi or dedicated machine can all be useful depending on what you want to run.

Suggested order
Choose hardware→Install Docker→Install Arcane→Choose apps→Configure storage→Deploy
02 · The foundation

Docker & Compose

Docker packages an application and its dependencies into a container. Docker Compose gives you a readable way to describe several containers, their networks, volumes and configuration together.

The goal here is not to hide Docker from you. The generator should make the first Compose file approachable, then let you inspect and learn from the result.

A simple Compose idea
services:
  jellyfin:
    image: jellyfin/jellyfin
    volumes:
      - ${MEDIA_ROOT}:/media
    restart: unless-stopped
03 · The bigger picture

How the stack fits together

A modular server is a collection of small tools with specific jobs. Some are independent. Others work best when connected.

Example media flow
Jellyseerr→Sonarr / Radarr→Download client→Library→Jellyfin

Bazarr can sit alongside Sonarr and Radarr for subtitles. Gluetun can provide a VPN network boundary for supported download traffic.

Dependency rule: the generator should distinguish between required, recommended and optional relationships. It should add required infrastructure automatically, but explain why it appeared.
04 · Keep it organized

Storage & folders

Storage is one of the most important decisions in a media server. Keep configuration data separate from the media you care about, and give downloads and libraries a predictable structure.

/volume1/
├── docker/
│   └── modular-media-server/
├── media/
│   ├── movies/
│   ├── tv/
│   └── music/
├── downloads/
│   ├── torrents/
│   └── incomplete/
└── photos/

The exact paths are configurable. The important part is consistency. Shared storage layouts can also make hardlinks possible for compatible workloads, avoiding unnecessary duplicate data.

05 · Getting around

Networking

Keep services on a private network by default. Expose only what you actually need, and use a reverse proxy, VPN or mesh VPN when remote access makes sense.

  • Do not expose administration interfaces casually.
  • Use strong passwords and generated secrets.
  • Keep Docker and application images updated.
  • Understand which container is allowed to reach the Internet and why.

08 · Keep it healthy

Updates & backups

Containers make updates convenient, but convenience should not replace backups. Keep important configuration and media protected before making changes.

  • Back up important application configuration.
  • Back up irreplaceable photos and personal data separately from the server.
  • Review release notes before major upgrades.
  • Keep a record of custom environment variables and integrations.
  • Test that backups can actually be restored.
